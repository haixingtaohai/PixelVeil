# PixelVeil · 像素面纱

一个**单文件、零依赖、完全本地运行**的像素置换图片加密器。输入密钥后，图片的每个像素会被确定性打乱成彩色噪点；只有使用**相同的密钥**和**同一张 PNG**，才能逐像素还原。

整个工具就是一个 `index.html`，双击即可离线使用，不上传、不联网、不依赖任何第三方库。

---

## 特性

- **单文件交付**：HTML / CSS / JavaScript 全部内联，无构建步骤、无外部依赖、无网络请求。
- **确定性加密**：同一密钥 + 同一尺寸必定生成同一张置换表，任何设备结果一致（不使用 `Math.random()`）。
- **严格互逆**：加密与解密采用同一张置换表，RGBA 按像素整体搬移，解密可逐字节还原原图。
- **无损输出**：结果固定通过 `canvas.toBlob(..., 'image/png')` 导出，避免 JPEG 有损压缩破坏像素。
- **密钥指纹校验**：状态区显示密钥指纹；加密结果内嵌无损标记，解密前自动核对密钥与尺寸。
- **解密前置检查**：校验 PNG 文件头、真实尺寸与标记，非 PNG 或被缩放/转存的文件会直接给出原因。
- **Canvas 自检**：读取为空、写入失败、导出尺寸异常都会明确报错，而不是静默产出噪点图。
- **图片放大预览**：单击图片在页面内全屏预览，支持双指捏合缩放、单指拖动、双击放大 / 复位、1 倍时下滑关闭。
- **移动端适配**：针对 iPhone 15 Pro 的视口、安全区与触屏操作优化，禁用了双击放大等浏览器手势。
- **实时进度条**：处理时在控制区显示当前阶段与百分比，大图也能看到置换表生成、像素置换、PNG 编码等进度。

## 快速开始

1. 下载并用浏览器打开 `index.html`（可离线）。
2. 在「密钥」中输入密钥，或点击「随机密钥」生成一个 16 字节的十六进制密钥，并妥善保存。
3. 点击「原图」区域选择图片，点击 **执行加密**，然后点击 **下载结果 PNG**。
4. 解密时切换到 **解密** 模式，载入刚才下载的加密 PNG，输入完全相同的密钥，点击 **执行解密**。

> 加密结果的文件名为 `原文件名_encrypted.png`，解密结果为 `原文件名_decrypted.png`。

### 使用流程示意

```text
原图 + 密钥 ──加密──> 彩色噪点 PNG ──传输 / 保存──> 同一密钥 ──解密──> 原图
```

## 加密原理

### 1. 密钥派生置换表

```text
key ──cyrb128──> h[0]（32 位种子）
        │
        └──> mulberry32(seed) ──> Fisher–Yates 洗牌 ──> perm[N]
```

- `N = 图片宽度 × 图片高度`（像素数量）。
- 置换表 `perm` 是一个长度为 `N` 的数组，内容为 `0 … N-1` 的确定性排列。
- 每一步只依赖密钥和像素数量，因此同一密钥、同一尺寸在任何设备上都会得到完全相同的 `perm`。

### 2. 像素置换

设原图像素数组为 `src`，输出为 `out`，`perm` 为置换表：

```text
加密：out[perm[i]] = src[i]
解密：out[i] = src[perm[i]]
```

RGBA 四个字节作为一个像素整体搬移，不拆分通道，因此颜色不会串位。

### 3. 为什么必须保存 PNG

置换后的像素值保持原样，只是位置被打乱。PNG 是无损格式，能完整保留这些值；JPEG 的有损压缩、截图、相册压缩、社交软件转发都会改变像素，导致解密无法还原。解密必须使用**加密时下载的原始 PNG 文件**。

---

## 文件格式与校验标记

加密结果在 PNG 的 `IEND` 之前写入一个标准 `tEXt` 文本块，关键字为 `pixperm`，内容格式为：

```text
1|<密钥指纹>|<宽>x<高>
```

- 该文本块**不改变任何像素数据**，只作为元信息存在。
- 解密时会读取并比对：
  - 文件必须是真正的 PNG（按文件签名和 `IHDR` 判断，而不是扩展名）；
  - 文件头尺寸必须与浏览器解码尺寸一致；
  - 当前密钥指纹必须与标记中的指纹一致。
- 标记被其他软件剥离时仍可尝试解密，只是无法提前核对密钥，界面会给出提示。

### 密钥指纹

密钥指纹取自 `cyrb128(key)` 的第二个 32 位结果并格式化为 8 位十六进制。它只用于比对两次输入是否一致，**不会写入用于置换的种子**。

### 密钥归一化

为了减少手机输入法带来的干扰，密钥在哈希前会：

1. 做 Unicode NFC 归一化；
2. 移除零宽字符等不可见格式字符（`U+200B–U+200D`、`U+2060`、`U+FEFF`）；
3. 去掉首尾空白。

密钥本身仍然区分大小写。

## 重要说明

- **必须使用 PNG**：结果固定导出 PNG；解密输入也必须是 PNG。JPEG / HEIC / WebP 等格式会改变像素，无法还原。
- **尺寸必须一致**：解密图的宽高必须与加密时完全相同；缩放、裁剪、润色都会改变像素数量，导致置换表错位。
- **密钥必须一致**：大小写、空格、输入法造成的字符差异都会改变密钥哈希。状态区的「密钥指纹」可用于核对。
- **请在手机浏览器中直接下载原图**：不要截图、不要经过相册转存、不要用聊天软件发送加密图，优先使用页面上的「下载结果 PNG」按钮。
- **大图处理**：点击执行后直接开始，不再弹出确认；控制区会显示实时进度条。超过约 1677 万像素时，部分手机（尤其 iPhone）的 Canvas 可能无法处理，建议先缩小图片。
- **半透明图片**：Canvas 的预乘 alpha 可能让半透明像素存在轻微精度损失，照片类不透明图片不受影响。

## 安全说明

本项目是**像素级视觉混淆工具**，不是现代密码学意义上的加密：

- 仅打乱像素位置，不改变像素值和颜色分布，统计特征仍然存在；
- 置换表由 32 位种子派生，种子空间有限，不适用于高敏感数据的长期保护；
- 请使用「随机密钥」生成的 32 位十六进制密钥，不要使用生日、手机号等弱密钥；
- 加密结果通过不安全的渠道传输时，请自行评估风险。

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 解密后仍是彩色噪点 | 密钥、尺寸或文件格式不一致 | 查看状态区：是否提示指纹不匹配、非 PNG 或尺寸不一致 |
| 提示「密钥指纹不匹配」 | 两次输入的密钥不同（大小写、空格、输入法） | 使用加密时保存的密钥重新输入 |
| 提示「输入文件不是标准 PNG」 | 加密图被转成 JPEG / WebP / HEIC | 重新从原始下载的 PNG 解密 |
| 提示「画布读取为空」或「画布写入自检失败」 | 图片超出设备 Canvas 限制 | 缩小图片后重新加密 |
| 下载的图无法解密 | 截图、相册转存或聊天软件压缩过 | 用页面「下载结果 PNG」按钮保存，并保持原文件不变 |
| 手机端无法打开文件 | 浏览器不支持文件选择或图片解码 | 使用 Safari / Chrome 等现代浏览器 |

## 浏览器兼容性

- 面向现代浏览器：Chrome、Edge、Firefox、Safari。
- 使用了 `createImageBitmap`（失败时回退到 `<img>`）、`ImageData`、`canvas.toBlob`、`crypto.getRandomValues`。
- Canvas 显式使用 sRGB 读写，减少 iPhone Display P3 色域带来的色值差异。
- 解密图片按原始方向解码，避免 EXIF 方向导致宽高互换。
- 已在桌面 Chrome 与 iPhone 15 Pro 视口模拟（393 × 852、DPR 3、触屏）下验证：
  - 160 × 120 与 800 × 600 图片加解密逐字节完全还原；
  - 错误密钥与非 PNG 文件被正确拦截；
  - 页面无脚本异常与横向溢出。
- 真机行为受浏览器版本与系统图片处理策略影响，建议使用最新版浏览器测试。
